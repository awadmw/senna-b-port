# C.1 机制演练 — fastboot boot（官方 stock，去填充 48 MB）

- 时间（本地）：2026-11-22 约 09:00（UTC+8）
- 设备：`78ad6b26`，senna / RE5860 / RMX3706_13.1.0.115(CN01)，slot `_b`，bootloader `unlocked: yes`，`verifiedbootstate=orange`
- 镜像：`build-chain/ota-evidence/boot-trimmed.img`（48,345,088 B，sha256 `2698dbbe0d4c638c9b0cde4c401a6b15f865a26049c89eb22518aca61eb9be09`）
  - 来源：官方 OTA 整分区 dump `boot.img`（201,326,592 B，sha256 `d9162a96…17ed7`）按 AVBf `original_image_size=0x2e1b000` 去填充
  - 头：v4，kernel 46,634,324 B @0x1000，ramdisk 1,698,305 B @0x2c7b000

## 目标
验证 senna 的 ABL 是否支持 `fastboot boot`（RAM 引导，不写分区、不改 slot）。

## 做法
```
adb -s 78ad6b26 reboot bootloader
fastboot boot build-chain/ota-evidence/boot-trimmed.img
```

## 实机输出（原样）
```
Sending 'boot.img' (47212 KB)                      OKAY [  1.122s]
Booting                                            OKAY [  0.515s]
Finished. Total time: 1.657s
```
进程退出码 0，总耗时 1,714 ms（实测 `Stopwatch`）。

fastboot 变量（bootloader 内）：
```
current-slot: b
product: taro
unlocked: yes
```

## 结果
- **fastboot boot 可用**（C.1 PASS）：ABL 接受并执行了 RAM 引导，无 `unknown command`、无 `Invalid boot image`。
- 设备 9 s 后 adb 回归，48 s 后 `sys.boot_completed=1`。
- 启动后状态：`ro.build.display.id=RMX3706_13.1.0.115(CN01)`、`ro.boot.slot_suffix=_b`、`ro.boot.verifiedbootstate=orange`、`uname -a: Linux localhost 5.10.149-android12-9-o-g36dae0b389f6 #1 SMP PREEMPT Fri Jul 14 18:48:37 UTC 2023 aarch64`。
- **root 如预期消失**：`command -v su` → `none`（RAM 里跑的是官方未打 Magisk 的 stock boot），下次正常重启回 `boot_b` 即恢复。分区/slot 未改动。
- 截图：`c1-after-boot.png`（5,216,388 B），系统 UI 正常。

## 结论
senna ABL 支持 `fastboot boot` → C.2（RAM 引导自研 shim）通路成立，无需改走 EDL/其他机制。
